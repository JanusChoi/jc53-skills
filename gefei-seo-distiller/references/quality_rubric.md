# 蒸馏质量审计 Rubric

## 硬门槛（必须全部满足）

1. 每个知识单元有至少一条在对应最新版本原文中能逐字定位的引文。
2. 原文 `content_sha256` 与抽取的版本相同。
3. 规则没有虚构指标、时点、方法、工具调用，声称第三方说的话没有未经证实归给作者。
4. 反例/例外条件没有因缩写而遗漏；不能把特例上升为全局规律。
5. 有利害关系、广告、平台算法或时效性影响时，正确标注。

## 语义审计（人工或另一模型）

对每类随机抽查，尤其优先抽查 `decision_rule` / `procedure`：

- **归属正确**：谁说的？是在肯定、质疑还是仅复述？
- **前提保留**：是否保留国家、阶段、付费/免费、SEO 与社媒等条件？
- **逻辑方向**：相关性是否被错解为因果？
- **执行完整**：输入、步骤、失败条件是否都来自证据或明确标为“待补”？
- **时间归属**：过去的建议能否照搬？如果不能，是否写出需重新核实项？
- **冲突意识**：新旧说法有没有被错误合并成无条件“统一标准”？
- **工程可用**：能否实际映射到 Tool、Workflow、Agent 测试？

每条记 `pass / needs_context / unsupported` 和原因。若关键规则被判 `unsupported`，必须返工；不要使用声称“90%准确”的虚构模型评分。

## 反证优先

综合阶段主动找“同主题相反证据”，优先审查最常被重复引用的规则，而不是只从高频段落中提炼越来越确定的信念。

## 源数据常见陷阱

- 公众号转载、群聊纪要、营销软文，不是第一人称博主实践。
- 图中文字和表格抓取丢失；正文字段可能只有预览摘要。
- 文章日期不完整，导致“现在/去年/上周”无法锚定。
- sitemap 文件 `lastmod` 并不能直接证明内容真正发生变更。
- Domain Rating/估计流量与 GSC 真实搜索点击不是一个口径。
- 新站成功案例有幸存者偏差，不能从几个赢家推出大概率成功。
